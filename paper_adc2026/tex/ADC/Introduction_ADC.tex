\section{Introduction}
\label{sec:intro}

High-dimensional approximate nearest-neighbour (ANN) search is a core primitive
in retrieval, recommendation, and vector databases. On a GPU, compressed search
is not governed by memory footprint alone: a representation can reduce bytes yet
raise lookup pressure or instruction issue, and an implementation can move the
same logical bytes and still accelerate. The systems problem is to map the
algorithm's structure to the hardware bottleneck rather than to assume that
smaller is faster.

JHQ~\cite{jhq} is a useful case study because its hierarchy exposes two costs of
different shape. After IVF routing, a compact primary code scores every routed
candidate at $O(n_c M)$; a per-dimension residual code is then read only for the
$c_k$ survivors of primary filtering, at $O(c_k d)$ with $c_k \ll n_c$. JHQ also
leaves the refinement factor $\alpha$ in $c_k=\alpha k$ externally specified.
The GPU port therefore raises two coupled questions with different causes:
\emph{how should the primary representation execute}, and \emph{how much of the
expensive hierarchy should execute}?

Our answer to the first is representation-specific. A conventional 8-bit ADC
table materialises 256 distances per subspace. JHQ builds each codeword as a
Cartesian product of one-dimensional levels, and squared Euclidean distance is
additive across them, so the same represented distance follows exactly from two
16-entry tables. This is not ``smaller is better''. Full-table state grows as
$256M$ entries while the two-way split grows as $32M$, an $8\times$ smaller
coefficient against a fixed on-chip budget, but each extra split costs another
lookup per candidate--sub\-space. Our answer to the second is a label-free
workload policy: sample queries from the running workload, compare the top-$k$
sets they return at a candidate budget against a generous reference, and take
the smallest budget that leaves them unchanged. It needs neither ground-truth
neighbours nor a learned difficulty model, at the cost of assuming a reasonably
stable query distribution.

We evaluate on six datasets from 768 to 3{,}072 dimensions, up to 17.8M vectors,
on one RTX 5090, and we test the alternatives we rejected rather than only the
implementation we kept. Six controls contradict the byte-count prediction, most sharply between the
four- and eight-way splits, which hold the same number of entries and differ
only in how many lookups reach them. Static disassembly then measures the
implicated variable directly, without a profiler: issued instructions per
candidate--sub\-space are $4.4$, $13.0$, $25.0$ and $50.4$ at $G{=}1,2,4,8$, query
time is close to linear in them wherever the table is resident, and the one
granularity whose table does not fit sits above that line by $4$--$120\%$ while
issuing the fewest instructions of any. The budget rule is worth
$1.044$--$2.653\times$ in steady state for at most $0.0048$ recall and repays
its calibration in a median of $1.75$ batches, while its sampling risk varies
enough by workload that no single sample size is safe.

The competitive picture is bounded and we state it as such. Among quantised IVF
methods JHQ leads through Recall@$10{=}0.95$ at large batch, owns the
high-recall end at high dimension, and indexes two datasets where the tested
cuVS IVF-RaBitQ build path runs out of memory. It is not the fastest system
measured: graph-based CAGRA-int8 is $1.6$--$2.9\times$ faster below
Recall@$10{=}0.95$ on every dataset where both run, at $5$--$8\times$ the build
time and a comparable code budget.

\smallskip\noindent\textbf{Contributions.}
\textbf{(i)} A decomposition of the primary scan's cost into an issue term and a
residency term, each measured: six controlled comparisons in which fewer bytes
or less state fails to predict throughput, and a static instruction count from
the disassembled kernel against which the residency penalty appears as the
residual.
\textbf{(ii)} An exact Cartesian factorisation of JHQ's primary distance table,
derived from separability the codebook already has rather than from a different
quantiser, together with the regime in which it pays.
\textbf{(iii)} A label-free, predictor-free policy for JHQ's residual budget,
evaluated on gain, quality cost, amortisation, and sampling risk.
\textbf{(iv)} An evaluation that reports where the compared systems are faster
than ours and where our evidence does not generalise.
