# 验收标准 / Acceptance criteria

**给谁用:** GPT 照 `WRITING_CARDS.md` 写草稿,你合并,我照这份清单核。清单**先于草稿存在**,所以我的意见能按档次给你,而不是四十条无序 bullet。

**三档:**

| 档 | 含义 | 你该怎么处理 |
|---|---|---|
| **A 改主张** | 这句话论文站不住,或者证据支持的是另一句 | 必须改 |
| **B 改数字** | 数值、出处或条件错了 | 必须改,但只动那个数 |
| **C 改措辞** | 意思对,表达会被误读 | 可选 |

**只有 A 档能挡住投稿。** B 档多数是一处替换。C 档我会给建议不给强制。

## 通用(每节都查)

必须有:
- 每个数值都能在 `paper_adc2026/README.md` 的证据表里找到出处
- 每个"更快/更小/更好"都带条件:哪个数据集、哪个召回、哪个批大小
- 每个 `[TBD]` 要么填了,要么在局限里明说

不得出现:
- 版本号(v47、v52、v57……)出现在正文
- 「最快」「最优」「普遍」这类无条件最高级
- 没有条件的百分比(「快 30%」——对谁?在什么召回上?)
- 把不同批次实验的百分比相加推出合成加速比

## §1 引言

**必须有**
1. 两个未解问题写清楚:结构该怎么执行、一个工作负载需要多少精化
2. 贡献列表与 §3/§4 的实际内容一一对应(不多不少)
3. 如果采用"机制"框架:开篇就说出**扫描受指令发射限制**,并预告四个实验
4. 数据规模一句(六数据集,最大 1780 万 × 1024 维)

**不得出现**
- CPU 加速比,除非 `[TBD]` 已填(**当前未填**)
- 「25×」形容 α 跨度 → 写「4 到至少 200(nprobe=128)」
- 结论里没有的主张

**A 档触发条件**:贡献列表里有 §3/§4 兑现不了的项;或者声称了普适优势。

---

## §2 预备

**必须有**
1. **主码本是笛卡尔积** —— 一维 Lloyd-Max 层级的笛卡尔积,所以码字节是 Ds 个 base-L 位
2. **可容许性规则 `Ds | B`**,以及 B=8 时 Ds ∈ {1,2,4,8}
3. **残差逐维**:`bpv = (d·Br+7)/8`,Br=8 时约 9 bit/维(主 1 + 残差 8)
4. 记号契约:`Q` 方阵、`r = y − ŷ_primary`、`ck = α·k`、批量形式 `Y = X Qᵀ`

**不得出现**
- 重推 JHQ 的训练算法(§3 用不到 Lloyd-Max 怎么解)
- 把 IVF 写成 JHQ 的一部分

**A 档触发条件**:§3 用到了 §2 没建立的性质(尤其是笛卡尔性质和 `Ds | B`);或 §2 有 §3/§4 从不引用的段落。

**判据一句话**:§3/§4 里任何需要回查原论文才懂的句子 = §2 漏了;§2 里任何 §3/§4 不引用的段落 = 多余。

## §5 相关工作

**必须有 —— 四条威胁,每条一个明确回应**

| 威胁 | 必须写出的区别 |
|---|---|
| 「这不就是 FastScan / Quicker ADC」 | 它们**改量化器**换小表(拿精度换);我们不改,**距离逐位相同**。无损/有损是这条轴 |
| 「参数自动调优早就有」 | FAISS ParameterSpace、自适应提前终止;区别是**无标签无预测器的输出稳定性**,作用于 JHQ 外部指定的参数,且对着穷举扫描验证过 |
| 「GPU ANN 已经很卷」 | IVF-RaBitQ / CAGRA / IVF-PQ 是基线,引用必需;写各自更强的工作区域 |
| 「JHQ 是别人的工作」 | 算法是原论文的,**执行路径和精化策略是本文的** |

**位置约定**:§4 留一段定位(威胁 ②),§3.3.1 留一句指向 §5(威胁 ①)。等到 §5 才回应太晚 —— 审稿人在读到贡献时就会起疑。

**不得出现**
- 「没有别的量化器能做分解」
- 声称采样调参本身新颖
- 把相关工作写成「它们都不如我们」

**A 档触发条件**:FastScan / Quicker ADC 未引;或无损/有损的分界没立;或把采样调参说成新的。

## §3 GPU-Native JHQ

**必须有**
1. **精确性论证**,而且立成一个轴:分解后**距离逐位不变**。这是与 FastScan / Quicker ADC 的分界 —— 它们改量化器换小表(拿精度换),这里不改
2. **FastScan 和 Quicker ADC 的引用**,在 §3.3.1 或 §5 出现
3. 记号:`Q` 是方阵正交变换,**不是降维**;残差 `r = y − ŷ_primary`,**不是 IVF 质心残差**
4. 训练依赖与代码一致:JL → 主码本 → 主码编码 → **IVF 质心 → 残差码本**
5. 分解的收益写成**随 M 变化的性质**,不是常数:M=96 时 −4%~+12%,M=384 时 +23%~+53%,机制是 256 项表在 M=384 是 384 KiB、放不进共享内存
6. 打包与转置分开:转置是合并访存(标准工程),打包是**指令数**(由 `Ds | B` 使能)
7. §3 结尾落在 `ck = α·k` 和「该精化多少个幸存者」

**不得出现**
- 「128 字节 cache line 浪费 75%」——**任何形式**
- 用代数上的 8× 条目缩减冒充加速比
- 「没有别的量化器能做分解」
- 把转置说成新颖性
- 「+6% 到 +14.5%,无一为负」

**A 档触发条件**:没有精确性论证;或没引 FastScan/Quicker ADC;或把分解写成一个常数加速比。

---

## §4 自适应层级精化

**必须有**
1. ε 定义为**整数槽位数**,且与 §6.3 的 0/1/2 消融是同一个量
2. 规则走**二分**;若提到停止行为,只能说「相对于被采样的一致性判据是保守的」
3. 单调性假设写出来并给论证:精确 top-ck 给出**嵌套候选集**,故不一致槽位数随 α 单调不增
4. 相关工作定位段落:FAISS ParameterSpace、自适应提前终止;区别是**无标签、无预测器的输出稳定性**
5. 回本模型,以及**平稳性假设**写成局限(漂移未测)
6. **S 按工作负载给,附实测风险** —— 不给常数

**不得出现**
- 「停在第一次拒绝,所以单边」(那是可选的线性模式)
- 「绝不会选得太小」
- 「S=32 是拐点」
- 「0.6–178.6 批」「中位数 2.7」(含四个未改变预算的自比行)

**A 档触发条件**:把 S=32 写成通用建议;或把单边性写成保证;或漏掉平稳性假设。

## §6 实验

**§6.1 必须有**
1. 统一计时边界:主机查询进 → 主机结果出
2. Recall@10,全程 k=10;α 与 k 耦合,跨 k 未测
3. 前沿 QPS 报稳态,**标定成本单独报**并经回本分析纳入
4. 等召回比值是**相邻实测点间的对数线性插值**,标明是插值,不外推
5. `JHQ_N_TRAIN = 39 × nlist`
6. **两个噪声地板,分开说**:跨 build 1e-3(训练不可复现),同索引配对 1e-4(只有 top-ck 并列在变)
7. **CPU 线程扫描**:208 段错误、64 明显差、16/32 在噪声内 —— 附线程数与 pinning
8. **原论文单线程测搜索**(AMD EPYC 9654),我们用多线程 —— 这是**对 CPU 更宽容**的选择,所以我们的加速比是保守的。**必须明说**,不能让读者自己发现
9. **CPU 前沿是 (α, nprobe) 的包络,不是固定 α** —— 原论文调 α∈{2,4,8},拿 α=100 跑 CPU 会让它白做 25 倍残差工作
10. 明说这**不是复现**原论文数字:主码长度、α、nprobe、硬件都不同(见 `data/cpu_provenance.md`)

**§6.2–6.7 必须有**
- 6.2:按工作区域写,附 RaBitQ 等召回表;分配失败要指明**所测配置**
- 6.3:α 跨度用删失区间;**留出验证的分布**(2000 次抽样)而非单次
- 6.4:三层分组(JHQ 专有 / `Ds|B` 使能 / 修正);**四条机制证据**
- 6.5:游标作为机制证据出现;复用实验称**受控代理**
- 6.6:等召回表;标注哪一格不可引用
- 6.7:构建与显存;缺口段叫 **other / unaccounted**

**不得出现**
- 把扫描端点画成或说成能力上限
- 「JHQ 显存更省」→ 写「处在不同的 显存–精度–吞吐 工作区」
- 诊断构建的 QPS 与头条 QPS 同表而不标注

**A 档触发条件**:任何等召回声明背后没有插值说明;或噪声地板混用;或 CPU 基线缺席而未在局限中明说;**或 CPU 基线用固定 α 而非 (α, nprobe) 包络**;**或声称复现了原论文的 CPU 数字**。
