## 0. 核验适用条件（导出时的检查，`pp_pilot/*/meta.json`）

| 检查项 | 结果 |
|---|---|
| 两个主电平严格对称 | `levels_symmetric = true`；c = 0.0243385509（768 维）、0.0121692754（3072 维） |
| 码本与电平不符的条目 | `codebook_level_mismatches = 0` |
| 每维比特数与电平 | 每维 1 bit，所有维共用 ±c |
| 字节内比特顺序 | 最高位对应子空间的第一维，bit 1 = +c |

所以 D_P = ‖q′‖² + d c² + 2c Σq′ − 4c z，其中 z = Σ_j q′_j b_j，是恒等式。

**候选集合：** 按 probe 顺序拼接各 list 的位置，与导出的 `cpos` 在 3 × 1000 条查询上**逐一相同**（不匹配的查询数为 0）。所以 FP64 的 D_prim 可以直接一一对应。

## 1. 冒烟测试（`1f359fb`，vogue，b = 8，1 轮）

## 2. 第一轮全量（`1ace056`）：统计与 5 种实现，三个数据集 × b ∈ {8, 1000}，7 轮 × 10 次

- **评分：** 最好的 Mailman（H2 r4）慢 1.7–5.3 倍；H1 慢 4–22 倍。
- **统计（top-512 list）：** list 内比特强偏置。
  - |p1 − ½| 均值：vogue 0.284、arxiv 0.361、openai3 0.195。
  - r = 8 时全 0 + 全 1 的比例：35%、52%、12%。
  - warp 内最大桶重复数：7.1 / 10.3 / 3.1，随机比特为 1.9。
- **字典：** 只有 arxiv 有空间（字节比 0.864，工作比 0.731）；vogue ≥ 0.959；openai3 为 1.000。
- **模型：** H2 每组每维 3 次共享内存操作，对 B0 的 1 次查表覆盖 4 维、32 个候选，比值约 12/r。r = 4 预测慢 3 倍，实测 1.7–5.3 倍。r = 8 受占用率限制，实测慢 5.5–12.5 倍。

## 3. 迭代 1：H2 r = 6（`9cee251`）

- **观测：** H2 r8 只有 2 warp/SM；H2 r4 每个候选的共享内存操作最多。
- **假设：** 如果瓶颈是每个候选每维的共享内存操作数，那么在占用率不受限时，速度比约为 r/12。
- **改动：** 只加了 r = 6：64 个桶，每 warp 8 KB，模式按字节存储。其余不变。
- **预测：** 比 B0 慢约 2 倍，好于 r4（慢 3 倍）和 r8（受占用率限制）。
- **实测：**
  - vogue b = 8：慢 2.18 倍，好于 r4（2.74）和 r8（5.5），符合预测。
  - 其他配置：只有 8 warp/SM（每个 block 35–45 KB，每 SM 2 个 block），不如 r4。b = 1000 时慢 2.8–3.7 倍。
- **结论：** 模型在占用率足够时成立；要追平 B0 需要 r ≈ 12，每个 lane 4096 个桶，放不下，不值得再做。

## 4. 迭代 2：H1z r = 8（`9cee251`）

- **观测：** 全 0 和全 1 模式占 35–52%（768 维），是 warp 内冲突最严重的两个桶。
- **假设：** 0 号桶不属于任何候选，可以直接跳过；全 1 桶属于全部 8 个候选，可以在寄存器里累加，最后加到每个 z 上。H1 的加速幅度应与偏置程度成正比。
- **改动：** 只改了 H1 r8 的累加分支，恢复阶段加一次 warp 求和。
- **预测：** arxiv 改善最多，vogue 其次，openai3 基本不变（只占 12%）。
- **实测（相对 H1 r8）：** arxiv 快 1.79 倍（b = 8）和 2.51 倍（b = 1000）；vogue 快 1.52 倍和 1.81 倍；openai3 为 1.07 倍和 1.00 倍。完全符合预测，但仍比 B0 慢 3.4–5.8 倍。
- **结论：** 偏置确实是 H1 冲突的来源，但消除它也追不上 B0。

## 5. 诊断（`49129bb`）

- **分阶段周期（clock64）：** 累加 88.6–99.7%，递推恢复 ≤ 7.5%，清零 ≤ 2.1%，写出 ≤ 3.8%。时间几乎全在累加。
- **SASS：** FP32 共享内存 `atomicAdd` 在 sm_80 中有 192 处、在原生 sm_120 编译中有 224 处 `ATOMS.CAST.SPIN`，即 CAS 自旋，Blackwell 上同样没有原生的 FP32 共享内存加法。
- **端到端占比：** B0 在扫描自身并行度下的评分时间，占 v70 扫描的 21–37%（b = 8）和 69–86%（b = 1000），占端到端的 11–22% 和 48–59%。
