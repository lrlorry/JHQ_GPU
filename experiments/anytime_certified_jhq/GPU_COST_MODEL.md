# GPU_COST_MODEL：最好情况下能省多少端到端时间

**证据等级：[推导]。** 本研究没有写 CUDA。离线门槛没有通过（EXPERIMENT_LOG.md），按预注册规则停止。

下面的估计故意偏乐观，用来说明“即使在最有利的假设下也不够”：
- 用 oracle 阈值；
- 假设扫描时间与 sector 读取量成正比；
- 不计任何额外开销。

## 1. 最好情况的上界

**输入：**
- B0 的分阶段时间：本 session 实测，`experiments/math_ablation/b0_results/stages/`，v65 论文配置，np128；
- 每查询 primary 扫描所占的 GPU 时间比例 f_scan；
- pilot 测得的 sector 读取比例 r_sec（oracle 阈值）。

**估算：** 端到端节省 ≤ f_scan·(1 − r_sec)。

| | f_scan（b = 8 / b = 1000） | r_sec（oracle 阈值） | 端到端节省上界（b = 8 / b = 1000） |
|---|---|---:|---|
| openai3 | 41% / 62%（177 / 433 µs，4297 / 6915 µs） | 0.884 | 4.8% / 7.2% |
| arxiv | 49% / 65% | 0.973 | 1.3% / 1.8% |
| vogue | 54% / 71% | 0.958 | 2.3% / 3.0% |

## 2. 上界之外还要扣除的开销（只列出，未量化）

1. **可部署的阈值比 oracle 松。** 需要先有完整计算过的候选；v63 的共享界在扫描开始时为 +∞，前面的块完全不能淘汰。
2. **warp 粒度。** 只有一个 warp 的 32 个候选全部停止，才能省掉这个 word 的加载指令。实测 warp 发射比例是 0.92，比 sector 比例高。
3. **检查点的计算。** 每个候选每个检查点要做一次上界计算和比较，C1/C2 还要求平方根和对数，增加寄存器压力。
4. **随机 word 顺序。** 每个查询要生成一个排列，扫描按排列取 word 行，地址不再连续递增。好在同一 word 行内仍然合并。
5. **分支发散。** 部分 lane 停止后，warp 的执行效率下降。

**历史参照：** v49 在 v53 上实现过同类的确定性 exit bound，实测收益约等于 0（`results/front6/NEGATIVES.md`）。本研究的 C1/C2/C3 实测都等于 C0，所以不会比它更好。

## 3. 结论

**系统上 NO-GO。** 即使在最乐观的假设下，openai3 的端到端节省上界也只有 4.8–7.2%，低于 brief 的 10% 门槛；768 维的两个数据集只有 1.3–3.0%。所以不进入 CUDA 原型。
