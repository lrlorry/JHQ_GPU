# COST_MODEL：精排预算减少能换来多少端到端时间

**证据等级：[推导]。** 本研究没有在 GPU 上运行任何新的搜索 kernel。

- brief 的离线 GO 没有达成（ITERATION_LOG.md“最终确认”），所以 GPU 原型没有做。
- `jhq_v67_import` 与 `demo_jhq_v67_repr_bench`（把离线编码导入 v65 管线、与原索引并排计时）已编译通过（`raw/build67.log`），但**没有运行**。
- 下文所有时间都由 `roq_cost_model.py` 从已有的实测阶段时间推导，输出在 `roq_cost_model.json`。

## 1. 模型

    E2E(T) = front + scan(T) + merge(T) + refine(T) + topk(T) + host + extra(method)

**各项的来源：**
- 每一项都是**实测曲线**。
  - 工作点：v65 在各数据集原始 α 下的阶段时间，来自 `experiments/pipeline_campaign/exp2`（v63 构建：b = 8 时 G = 8 并开共享界，b = 1000 时 G = 0）。
  - 对 T 的依赖：取 v62 降 α 扫描中 scan、merge、refine、topk 对 ck 的曲线，在 log T 上插值，并在 T = ck 处对齐到 v65 的实测值。
- front（旋转、质心、选 list、建表）与 host 不随 T 变化。

**primary scan 对 T 的依赖只来自选择缓冲区。** 对所有按维的规则（median、mean、lloydmax、rank-loss），读的 bit、查表次数和表的大小都与论文索引相同：电平变了，表的结构不变。

**extra 项：**

| 规则 | extra |
|---|---|
| 按维（第 2、3 轮） | 0。建表时读 2d 个电平而不是一个 c，相对 front 可忽略 |
| 按 list（第 5 轮） | 每个（查询，list）一张表。下界：把建表并入扫描，约多 1/4 的扫描工作；上界：nprobe × 实测的单表构建时间 |

**比较方式：** 两边都取验证集上匹配 recall 的预算，即方法的 T_V 与 JHQ 的 T_J。这等价于与“α 重新调到同一 recall 的 v65”比较，而不是与原始 α 的 v65 比较。测试集在这两个预算上读到的 recall 差见第 3 节。

## 2. 结果

| 数据集 | 方法 | T_V vs T_J | b = 8：JHQ → 方法（µs） | b = 8 节省 | b = 1000：JHQ → 方法（µs） | b = 1000 节省 |
|---|---|---|---|---:|---|---:|
| arxiv | **median** | 320 vs 750 | 447 → 348 | **22.1%** | 4381 → 3863 | **11.8%** |
| arxiv | mean | 375 vs 750 | 447 → 366 | 18.0% | 4381 → 3959 | 9.6% |
| arxiv | lloydmax | 480 vs 750 | 447 → 395 | 11.6% | 4381 → 4109 | 6.2% |
| arxiv | jhq_re（JHQ 的离线复现，噪声参照） | 625 vs 750 | 447 → 426 | 4.7% | 4381 → 4270 | 2.5% |
| arxiv | list_median（下界成本 / 上界成本） | 320 vs 750 | 447 → 404 / 561 | 9.6% / −25.6% | 4381 → 4580 / 6275 | −4.5% / −43.2% |
| vogue | list_median（下界 / 上界） | 480 vs 640 | 422 → 454 / 602 | −7.6% / −42.7% | 4611 → 5322 / 6901 | −15.4% / −49.7% |
| vogue | median | 验证集达不到目标 | — | — | — | — |
| openai3 | median | 30 vs 25 | 432 → 432 | −0.1% | 6966 → 6972 | −0.1% |

负数表示变慢。arxiv 的阶段拆分（b = 8，JHQ → median）：
- scan 223 → 180 µs，refine 95 → 48 µs，merge 与 topk 合计 31 → 22 µs；
- front 77 µs 与 host 20 µs 不变。

b = 1000 时扫描占 65%，它对 T 不敏感，所以同样的候选减少只换来一半左右的节省。

**怎么读：**
1. **median（arxiv）** 是唯一在两种 batch 下都有正节省的方法：b = 8 约 22%，b = 1000 约 12%。精排预算减少 57%，却只换来 12–22% 的端到端节省，因为 primary 扫描和前端不随 T 缩小。
2. **按 list 的规则**即使在 arxiv 上候选减少 57%，也被每个（查询，list）一张表的开销抵消，多数情形是变慢。这条路即使排序更好，也需要先解决查表成本。
3. **jhq_re 的 4.7%** 来自残差重训的噪声：同一个方法，T_min 在网格上跳了一档。它给出了这个模型下“看起来像收益”的噪声量级，所以单数据集上低于约 5% 的推导节省都不应当作收益。

## 3. 测试集在这两个预算上的读数

`eval_final_test.json` 的 `test_matched` 项：median 取验证集的 T_V，JHQ 取验证集的 T_J，在测试集 400 条查询上逐查询配对比较。

| 数据集 | 预算 | recall 差（pp，95% CI） | 变差的查询 | 最坏一条 |
|---|---|---|---:|---|
| arxiv | median@320 vs JHQ@750 | 0.00 [−0.28, +0.30] | 4.3% | 少 1 个近邻 |
| openai3 | median@30 vs JHQ@25 | +0.08 [−0.10, +0.25] | 1.5% | 少 1 个近邻 |

arxiv 上，按验证集选的 320 个候选在测试集上与 JHQ 的 750 个候选 recall 打平。所以上表 22% / 12% 的推导节省在测试集上**不以 recall 为代价**。

## 4. 局限

- **这是推导，不是测量。**
  - 插值用的是 v62 的降 α 扫描曲线，没有用 v65 本身的 T 扫描；
  - 按维规则的表值换成两电平后，LUT 构建时间假设不变，没有实测。
- **离线复现与论文索引不完全相同。** 比较对象是论文索引本身；离线变体的残差码本由同一流程重训，与论文索引的码本并不逐位相同（THEORY.md 1）。
- **只有 arxiv 有正收益。** 对 vogue 和 openai3，这个模型给不出任何节省。
- **要变成可报告的 GPU 结果，还需要：**
  - 运行 `demo_jhq_v67_repr_bench`（b = 8 / 32 / 256 / 1000），与 α 重新调优后的 v65 比较；
  - 预计 GPU 时间在 20 分钟以内。
  - 本研究按 brief 的门槛没有做这一步。
