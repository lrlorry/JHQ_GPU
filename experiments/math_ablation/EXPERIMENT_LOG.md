## V2：EVT 动态 list 剪枝（离线模拟，`evt_sim.py`）

**设置：**
- list 按查询到 list 中心的距离排序；中心取旋转空间中的 list 均值，作为路由质心的近似。
- 先扫前 L1 个 list 得到 τ；之后每 16 个 list 为一个阶段，风险低于 ε 的 list 跳过。
- 风险模型只用校准集拟合。

**能省多少（验证集）：** 全扫描、oracle 与 EVT 的扫描比例如下。

| | 全扫描 recall | oracle：只扫含 top-ck 的 list | 不损失 recall 时最好的 EVT 规则 | 降 nprobe 在同 recall 下 |
|---|---:|---|---|---|
| arxiv | 0.9790 | 81.1% 的候选（97 个 list） | gev，L1 = 8，ε = 0.1：96.3% | 100% |
| vogue | 0.9575 | 61.4%（73 个 list） | iid_evt，L1 = 16，ε = 0.1：96.9% | 100% |
| openai3 | 0.9025 | 12.3%（13.6 个 list） | gev，L1 = 16，ε = 0.003：93.0% | 100% |

**允许小幅损失 recall 时，EVT 与降 nprobe 的候选比例之比**（小于 1 表示 EVT 扫得更少）：

| 允许损失 | ≤ 0.1 pp | ≤ 0.25 pp | ≤ 0.5 pp | ≤ 1 pp |
|---|---:|---:|---:|---:|
| arxiv | 0.996 | 1.049 | 1.037 | 1.307 |
| vogue | 0.955 | 0.945 | 0.989 | 0.915 |
| openai3 | 0.942 | 0.885 | 0.784 | 0.809 |

**概率校准（验证集 100 条查询，L1 = 16）：**
- i.i.d. 极值公式严重失准：
  - arxiv 上预测 0.1–1% 的 list，实际有 33% 含有更好的候选；
  - openai3 上预测 > 0.5 的 list，实际只有 24%。
  - 这正是候选不独立、不同分布的后果。
- GEV 也失准：vogue 上预测 1–5% 的，实际为 26%。
- 只有校准后的逻辑回归接近对角线：openai3 上预测 2.8% 对应实际 2.5%，预测 10% 对应 9.9%。

**初步判断：**
- 不损失 recall 时，候选读取只减少 3.1–7.0%，离 oracle 的上限（19% / 39% / 88%）很远。可以用的统计量（τ、中心距离、list 大小、名次）预测不了哪些 list 没有 top-ck 候选。
- openai3 上允许 0.25–1 pp 损失时，比降 nprobe 少扫 12–22%。但这是用 recall 换来的，不是无损加速。

## V1：真实 ANN 评估（eval_e8，校准 + 验证，配对差单位 pp）

| | T_min（校准 / 验证）：JHQ → E8 | E8 − JHQ 离线复现，T = ck/8 … ck | 只换 primary（E8 排序 + 论文 D_H）− JHQ | 层次重建 MSE：JHQ 离线复现 → E8 | 全 IVF recall（验证）：JHQ → E8 |
|---|---|---|---|---|---|
| arxiv | 875 → 750 / 750 → 750 | −0.08 … +0.18，CI 都含 0 | −0.17 … +0.05，CI 都含 0 | 2.83e-5 → 1.88e-5（−34%） | 0.9805 → 0.9820 |
| vogue | 560 → 400 / 640 → 400 | T=80：+0.40 [−0.22, +1.02]；T=640：+0.10 [−0.10, +0.32] | T=80：+0.35，CI 含 0 | 4.13e-5 → 2.40e-5（−42%） | 0.9575 → 0.9580 |
| openai3 | 40 → 30 / 25 → 25 | T=10：**+0.75 [+0.05, +1.45]**；T=20：**+0.27 [+0.07, +0.47]**；T=40：+0.08，CI 含 0 | T=20：+0.23 [+0.07, +0.42] | 4.66e-5 → 2.58e-5（−45%，按子空间 scale） | 0.9025 → 0.9030 |

**补充：** 按子空间 scale（E8g）在 arxiv 上明显更差（T=125 处 −1.1 pp，CI 在 0 以下），vogue 上略差，openai3 上持平。所以后续只用全局 scale。

**解读：**
- primary 的排序几乎不变：随机负例误排序率在 ±5% 以内，只换 primary 时各 T 的差都在 0 附近，openai3 的小预算处除外。
- 收益主要来自残差：primary 误差小了，256 级残差码本能覆盖更窄的范围，最终重建误差降低 34–45%，全 IVF 上限提高 0.05–0.15 pp。
- vogue 上 T_min 的 −29% / −37% 是平台效应：E8 的平台略高，恰好跨过目标；固定 T 的配对差都不显著。这与 rank-optimal 研究第 5 轮在 vogue 上的情形相同。


## V3：重新编码（rdbuild）

- **打包与正确性：** 所有分配都按真实变位宽打包，每向量 d 字节；首尾块的解包与编码逐位一致。

- **openai3：** 四种分配都是全部 8 bit。按构造，它的码与 JHQ 离线复现相同，所以重新编码中途停掉了（Python 按位打包约需 30 分钟），评估也跳过 openai3（`rd.py` 中注明）。
