## 二、V1 E8-JHQ：用 E8 格码本替换 {±c}⁸

### 2.1 数学思想

**JHQ 的 primary：** 每个 8 维子空间是一个立方体码本 {−c, +c}⁸。它是 8 个一维二值量化器的笛卡尔积，所以查表可以拆成 16+16。

**E8 的做法：** 换成 E8 格的 240 个根（第一壳层，8 维的最优接吻配置），再加 16 个 ±2e_i，共 256 个码字。
- 每 8 维仍然 8 bit；码字两两最小距离² = 2。
- 一个全局 scale 由训练向量拟合。
- 高码率格量化理论说 E8 比立方体好 0.65 dB；但本题是 1 bit/维、有限的球面码，增益只能实测。

### 2.2 源码修改

- **离线：** `v1_e8/implementation/e8.py` 构造码本并核验（全部属于 E8、两两不同、对称），实现暴力编码器与结构化编码器（三类码字各自取最大内积，再按完整距离比较），拟合 scale，并按 JHQ 的流程重训残差。
- **GPU 原型：** `jhq_v68_e8/`。
  - 把 v47 起的 16+16 分解表换回每个子空间完整的 256 项表；E8 不是笛卡尔积，只能这样做。
  - import_state 改为直接接收码本。
  - `examples/demo_jhq_v68_e8_bench.cu` 在同一套 v65 管线里并排测两种表示：A 为论文索引走 256 项表，B 为 E8 走 256 项表。导入前核对 list 布局。

### 2.3 正确性 [离线实测]

- 码本：256 个码字两两不同，全部属于 E8（112 个整数根 + 128 个半整数根 + 16 个轴向点）。
- 编码器：结构化编码器与暴力编码器在高斯、t₃ 重尾、码字加噪声三类输入上距离完全一致。
- 最近 ≠ 最大内积：在 68.6% 的样本上两者不同，轴向码字的范数更大（brief 的提醒属实）。

### 2.4 结果

**高斯样本上的每维 MSE**（独立复现）：

| 码本 | 每维 MSE |
|---|---:|
| JHQ 的立方体（c = 0.6745σ） | 0.3787 |
| 1-bit Lloyd–Max 立方体 | 0.3634 |
| E8 | **0.3195**（比 Lloyd–Max 低 12.1%） |

**真实数据 [离线实测]：**

| | primary MSE（E8 / JHQ） | 层次重建 MSE（E8 / JHQ 复现） | 全 IVF recall（验证） | T_min（校准 / 验证）JHQ → E8 | 固定 T 的配对差（E8 − JHQ 复现） |
|---|---:|---:|---|---|---|
| arxiv | 0.853 | 0.66 | 0.9805 → 0.9820 | 875 → 750 / 750 → 750 | 全部不显著 |
| vogue | 0.845 | 0.58 | 0.9575 → 0.9580 | 560 → 400 / 640 → 400（平台效应） | 全部不显著 |
| openai3 | 约 0.84 | 0.55 | 0.9025 → 0.9030 | 40 → 30 / 25 → 25 | T=10：+0.75 pp [+0.05, +1.45]；T=20：+0.27 pp [+0.07, +0.47]；T=40 不显著 |

**GPU [GPU 实测]：**（填写）

### 2.5 为什么

- E8 降低的是 primary 的**平均**重建误差，近邻之间的排序几乎没变：随机负例误排序率在 ±5% 以内，只换 primary 时各 T 处的差都接近 0。这与 rank-optimal 研究反复看到的“MSE ≠ 排序”一致。
- 收益主要通过残差体现：primary 误差变小后，256 级残差码本覆盖的范围更窄，最终重建误差降低 34–45%，recall 平台提高 0.05–0.15 pp。但平台本来就接近全 IVF 上限，可提升的空间很小。
- **代价：** 失去 16+16 分解后，每个查询的表从 12 KB / 48 KB 变成 96 KB / 384 KB，超出共享内存时只能读全局内存。仓库里 v59 的历史实测是 nprobe 128 时慢 2–4%（M = 96）和约 22%（M = 384）。本轮实测见上表。

## 三、V2 EVT-JHQ：按极值风险跳过 IVF list

### 3.1 数学思想

**极值公式：** 若一个 list 内的候选距离 i.i.d.，则

  P(min D < τ) = 1 − (1 − F(τ))ⁿ，

其规范化极限为 GEV 分布。

**做法：** 先扫最近的 L1 个 list 得到 top-ck 门限 τ，之后每 16 个 list 为一个阶段，风险低于 ε 的 list 不读。风险只用读 list 之前就有的量：τ、查询到 list 中心的距离、list 大小、名次。

**比较对象：** 四种风险模型——全局分箱、i.i.d. 极值公式、按 list 大小分档的 GEV、校准后的逻辑回归。

### 3.2 源码

`v2_evt/implementation/evt_sim.py`：在论文索引的真实探查候选上做离线模拟。模型只用校准集拟合，ε 在验证集上选，测试集确认。

### 3.3 结果 [离线实测]

| | 全扫描 recall | oracle（只扫含 top-ck 的 list） | 不损失 recall 的最好规则 | 降 nprobe 在同 recall 下 |
|---|---:|---|---|---|
| arxiv | 0.9790 | 81% 的候选 | 96.3% | 100% |
| vogue | 0.9575 | 61% | 96.9% | 100% |
| openai3 | 0.9025 | 12% | 93.0% | 100% |

**允许损失 recall 时：**
- arxiv 上 EVT 比降 nprobe 还差；
- vogue 上好约 5%；
- openai3 上损失 0.25–1 pp 时少扫 12–22%。这是用 recall 换来的，不是无损加速。

**概率校准：**
- i.i.d. 公式在 arxiv 上预测 0.1–1% 的 list，实际有 33% 含更好的候选；
- GEV 同样失准；
- 只有逻辑回归接近对角线。

### 3.4 为什么失败

- **候选不是 i.i.d. 样本。** 同一 list 的成员共享位置，到查询的距离强相关，所以 i.i.d. 极值公式和 GEV 都失准。
- **可用特征不够。** 读 list 之前能拿到的量（中心距离、大小、名次）区分不了“含不含 top-ck 候选”。所以即使是校准好的模型，也离 oracle 很远。
- **GPU 收益也不够。** primary 扫描占端到端 41–62%，少扫 3–7% 只对应 ≤ 4% 的端到端收益；多阶段扫描又要在阶段之间同步，降低并行度。

所以不做 GPU 原型，判 **NO-GO**。

## 四、V3 RD-JHQ：残差码率分配

### 4.1 数学思想

在 Σb_m·8 = 8d 的约束下，按率失真理论分配每个子空间的残差位数。高斯反向注水 b_j = ½log₂(λ_j/θ) 只作参考，实际按实测的失真–码率曲线做贪心整数分配，以及用校准查询加权。

### 4.2 源码

`v3_rd/implementation/rd.py`：
- 统计残差分布；
- 每个子空间按 2^b 级重训码本（b ∈ {6, …, 10}）；
- 把码按真实变位宽打包成比特流，每向量仍是 d 字节；
- 往返测试逐位一致；
- 在候选上评估。

### 4.3 结果 [离线实测]

| | 残差方差变异系数：按维 / 按子空间 | 高斯注水上限：按维 / 按子空间 | 最优整数分配 | 预测残差 MSE | recall |
|---|---|---|---|---|---|
| arxiv | 0.25 / 0.087 | −2.6% / −0.4% | 7 个子空间 7 bit、82 个 8 bit、7 个 9 bit | −2.5% | （填写） |
| vogue | 0.34 / 0.137 | −4.3% / −0.9% | 全部 8 bit | 0 | 与均匀分配逐位相同 |
| openai3 | 0.12 / 0.041 | −0.7% / −0.1% | 全部 8 bit | 0 | 与均匀分配逐位相同 |

**正确性旁证：** vogue 上四种分配的层次重建 MSE 都是 4.1313e-5，与 JHQ 离线复现完全相同。

### 4.4 为什么失败

- 码率分配要求各分量的方差不均；JHQ 的 JL 旋转（随机正交矩阵）恰好把方差摊平了。SAQ 能从分配中获益，是因为它先做 PCA，让方差集中。
- 每多 1 bit，实测失真只降到约 1/2，不是高码率理论的 1/4，进一步压缩了收益。
- 变位宽解码在 GPU 上要做跨字节的位提取，比按字节读慢。没有质量收益时，不值得做 GPU 原型。

## 六、新颖性

详见 NOVELTY_AUDIT.md，结论是三者都不构成算法创新：
- **E8：** 是已有工具的直接应用。最接近的是 QuIP#（2024）的 E8P 码本，用于 LLM 权重量化。
- **EVT 剪枝：** 是已有路线（学习式提前终止、ConANN 的保形保证、CLIP 的几何下界）的简单变体；其中“极值公式”在真实数据上不成立。
- **码率分配：** 是经典工具的应用；在 JL 旋转之后，它的前提已经不存在。
