# V1 E8-JHQ：理论与前提

## 1. JHQ 的 8D / 8-bit primary [源码]

**码本与预算：**
- 每个 8 维子空间的码本是 {−c, +c}⁸：8 个 bit，每维 1 bit，所有维共用 c = 0.6745σ（rank-optimal 研究 THEORY.md 1）。
- 三个工作负载都是 M = d/8 个 8D 子空间、每子空间 8 bit（arxiv / vogue M = 96，openai3 M = 384），正好是 brief 的“8D / 8-bit”。没有改变 bit 预算的配置。

**距离计算：**
- 立方体码本是两个 4D 立方体的笛卡尔积，所以 ADC 表可以分解成两张 16 项的表（16+16）；
- 打分为 D_P = ‖q′‖² + 8c²·M − 2c⟨q′, s⟩，排序只依赖 ⟨q′, s⟩。

## 2. E8 码本 [证明，`e8.py test` 核验]

**E8 格：** 偶坐标系下 E8 = {x ∈ ℤ⁸ ∪ (ℤ + ½)⁸ : Σx_i ≡ 0 (mod 2)}。

**取 256 个码字：**

| 类 | 形式 | 个数 | 范数² |
|---|---|---:|---:|
| 1 | (±1, ±1, 0⁶)，所有位置与符号 | C(8,2)·4 = 112 | 2 |
| 2 | (±½)⁸，负号个数为偶数 | 2⁷ = 128 | 2 |
| 3 | ±2e_i | 16 | 4 |

- 前两类合起来就是 E8 的 240 个根，即第一壳层，也是 8 维的最优接吻配置；
- 第三类是第二壳层（2160 个向量）中的 16 个；
- 码字两两之间最小距离² = 2。
- 量化码本取 s·C_E8，标量 s 只由训练向量决定：全局一个，或每个子空间一个（grouped）。

**两类码字范数不同，最近码字 ≠ 最大内积：**

  ‖x − s c‖² = ‖x‖² − 2s⟨x, c⟩ + s²‖c‖²。

**结构化最近码字 [证明]：**
- 在同一范数类内，最近等价于最大内积，每类的最大内积有闭式：
  - 类 1：取 |x_i| 最大的两个坐标，配上它们的符号；
  - 类 2：取 sign(x)，若负号个数为奇数，就翻转 |x_i| 最小的那个坐标（D8 + ½ 陪集的标准译码）；
  - 类 3：|x_i| 最大的坐标。
- 三个候选再按完整距离比较。复杂度 O(8)，与暴力搜索 256 个码字的结果逐点一致（距离差 0，见 `e8_test.json`）。

**ADC：**
- T_m[k] = ‖q′_m‖² − 2s⟨q′_m, c_k⟩ + s²‖c_k‖²，每个子空间需要一张完整的 256 项表；
- E8 的根不是低维码本的笛卡尔积，无法像立方体那样拆成 16+16。

## 3. 预期：E8 在高斯源上能降低多少 MSE？

**高码率格量化理论：** E8 的归一化二阶矩 G(E8) = 0.0717，ℤ 为 1/12 = 0.0833，相差 0.65 dB。这个结论只适用于高码率、无穷格。

**本题的设定不同：** 每维 1 bit、有限的 256 点壳层码本、高斯源。这是一个球面码加两档半径的问题：
- 立方体的 256 个角点在同一个球面上，相邻夹角 41.4°；
- E8 的根同样在一个球面上，最小夹角 60°，覆盖更均匀。
- 量化增益只能数值计算，见 `e8_test.json` 的 `gaussian_mse_per_dim`，与 1-bit Lloyd–Max 的 1 − 2/π = 0.3634 对照。

**真实数据偏离各向同性高斯：** arxiv 有很强的均值偏置。E8 码本和 JHQ 的立方体一样以 0 为中心，所以 V1 不处理偏置问题：偏置问题由 rank-optimal 研究单独处理，两者正交。

## 4. 排序 ≠ MSE

rank-optimal 研究的教训是：primary 的 MSE 降低并不保证近邻排序更好（那里第 3、4、5 轮都是反例）。所以 V1 的判据是在同一批 IVF 候选上的 recall–T 与配对差，MSE 只作解释。

## 5. 正确性条件（必须同时满足）

1. 256 个码字两两不同，且都属于 E8；
2. 快速编码器与暴力编码器的距离完全相同；
3. 新的 primary 必须配一个按 JHQ 流程重新训练的残差。不能拼接旧残差码本：`E8|JHQ-DH` 只用于隔离 primary 的作用，不算正式结果。

## 6. GPU 代价的先验估计（待实测）

| | JHQ | E8 |
|---|---|---|
| 每查询表大小 | M × 2 × 16 个 float：d = 768 时 12 KB，d = 3072 时 48 KB | M × 256 个 float：96 KB / 384 KB，超过单个 SM 的共享内存 |
| 每候选每子空间 | 两次 16 项查表 | 一次 256 项查表（表在全局内存或 L1 中），或按码字结构解码约 8 次加法 |

所以即使 recall–T 改善，GPU 上也可能被查表成本抵消。只有离线收益通过门槛，才实现并实测 GPU 原型。
