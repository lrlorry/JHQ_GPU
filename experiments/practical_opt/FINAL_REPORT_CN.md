## 结论

1. **第 1 项：median 阈值在 GPU 上的实测。效果因数据集而异，不是通用改进。**
   - arxiv：相同 recall 下，b ≤ 32 时快 1.26–1.41 倍，b ≥ 256 时快 1.11–1.21 倍；最高 recall 也从 0.9774 提到 0.9799。
   - vogue：最高 recall 只有 0.9630，达不到论文工作点的 0.9644。NO-GO。
   - openai3：与原索引完全相同（1.00 倍）。
2. **第 2 项：v69 精确选 probe。GO。**
   - 结果与 v65 逐位相同：
     - 1792 个对抗性合成用例 0 失败；
     - 三个数据集的 probe 与 primary top-ck dump 逐字节相同。
   - 端到端：b = 8 时快 1.07–1.17 倍，b = 1000 时快 1.03–1.05 倍。
   - probe 选择阶段从 53–78 µs 降到 15–23 µs（b = 8）。
3. **可选部分：v70 用 FP16 做质心打分（非精确）。GO。**
   - 论文 α 下三个数据集的 recall 完全不变；probe 集合平均重合度 ≥ 0.9995。
   - 在 v69 基础上再快 1.02–1.11 倍；质心阶段快 2–3 倍。
4. **合计 v65 → v70：b = 8 时快 1.10–1.29 倍，b = 1000 时快 1.07–1.10 倍。** openai3 收益最大（b = 8 时 1.29 倍）。
5. **新发现，未实施：v65 扫描的候选缓冲在某些 α 下有一个 25–40% 的性能断崖。**
   - 论文的三个工作点都不在断崖上，但 recall–QPS 曲线上的一些点在。
   - 建议作为下一项（第五节）。

## 一、第 1 项：median 阈值的 GPU 实测

**方法：**
- 程序：`demo_jhq_v67_repr_bench`，在同一进程里依次测两种表示，都走 v65 的搜索：
  - A：论文索引；
  - B：用 `experiments/rank_optimal_quantization/export_variant.py <tag> median` 导出的 median 阈值表示。
- 两者的旋转、IVF list 和位置都相同。
- 每种表示各扫一组 α；b = 8、32、256、1000，各 3 轮。
- median 阈值只由 base 数据算出，没有用到任何查询。
- 原始输出在 `median_results/`；比较由 `analyze_median.py` 完成。

**比较方式：** 在每个 batch 下，对一个目标 recall，取各自 recall 不低于目标的点中 QPS 最高的一个，再求比值。

**arxiv（论文 α = 100）：**

| b | 目标 recall | A 最佳点（α，recall，QPS） | B 最佳点（α，recall，QPS） | B/A |
|---:|---|---|---|---:|
| 8 | 0.9766（论文 α） | 100，0.9766，16690 | 32，0.9771，23398 | **1.40** |
| 8 | 0.9763（A α = 75） | 75，0.9763，18525 | 32，0.9771，23398 | 1.26 |
| 32 | 0.9764（论文 α） | 100，0.9764，54678 | 32，0.9769，76998 | **1.41** |
| 256 | 0.9771（论文 α） | 100，0.9771，149894 | 40，0.9780，169876 | **1.13** |
| 1000 | 0.9766（论文 α） | 100，0.9766，222055 | 32，0.9771，268161 | **1.21** |
| 1000 | 0.9763（A α = 75） | 75，0.9763，239065 | 32，0.9771，268161 | 1.12 |
| 1000 | 最高 recall | A 0.9774 | B 0.9799 | |

A 在 α = 75 的 recall 只比 α = 100 低 3 个近邻（共 10000 个），所以较保守的说法是：b ≤ 32 时 1.26 倍，b ≥ 256 时 1.11–1.12 倍。

**vogue（论文 α = 64）：**
- 同一 α 下 B 的 recall 比 A 低 0.0008–0.0022：B 最高只有 0.9630，而 A 在论文工作点是 0.9644。
- 在 A 的最低 recall 点（α = 32，0.9622），B 的最佳点只有 A 的 0.82–0.88 倍。

**openai3（论文 α = 4）：** α ≥ 3 时 B 与 A 的 recall 相差 ≤ 0.0002；α = 2 时 B 低 0.0004–0.0009。QPS 相同，比值 1.00。

**判读：**
- 与 rank-optimal 研究的离线结论一致：只有 arxiv 受益（离线测试集候选数减少 57%），vogue 受损，openai3 不变。
- 要部署，只能在建索引时用验证查询对每个数据集二选一，不能作为通用替换。
- 附带：B 在 arxiv 的最佳点（ck = 250–400）离第五节的断崖很近。修复断崖后，B 的优势可能更大，未测。

## 二、第 2 项：v69 精确选 probe

### 设计（`jhq_v69_probesel/search.cu`，`select_probes_kernel`）

**v65 的做法：**
- 每个查询一个 block；
- 把质心距离流式写进缓冲，缓冲大小 cap = 2 的幂且 ≥ nprobe + BLOCK（1024 或 2048）；
- 缓冲满了就做一次完整的 bitonic 排序：55–66 个以 barrier 分隔的阶段，每个查询 3–4 次；
- 最后由单线程累加 list 长度。
- b = 8 时整卡只有 8 个 block 在做这些串行工作。

**v69 的做法：** 仍是每个查询一个 block，结果的集合和顺序都与 v65 相同：按（距离，list id）取最小的 nprobe 个，并列时 id 小者优先。
1. **基数选择：**
   - 距离先映射成保序的 32 位 key：两个零映射到同一个 key，与浮点比较一致；
   - 做 4 遍 8-bit 直方图，得到第 k 小的 key K*，以及等于 K* 的 key 要取几个。
   - 直方图每个 lane 一份副本（32 KB）。原因：key 的首字节是符号位加指数高位，大多数距离相同，第一遍几乎全落进少数几个 bin；如果只有一份直方图，原子操作会串行化最多 32 路。
2. **收集：** 一遍取出全部 key < K* 的元素；等于 K* 的元素按 list id 从小到大取，保持 v65 的并列规则。
3. **排序：** 对选出的 k 个元素按（距离，id）计数求名次。只需两个 barrier，不用排序网络。
4. **偏移：** list 长度的前缀和改用 block scan。

距离在每一遍都用同一条 `__fmaf_rn(-2, dot, ‖c‖²)` 计算。因为 2·dot 是精确的，这也就是 v65 算出的位。

### 正确性

1. **核函数单测（`probe_select_test.py`）：**
   - 做法：
     - 从 v65 和 v69 的 `search.cu` 原文中截取两个核函数，编进同一个程序；
     - 用相同输入运行，逐字比较 probe id、偏移和每查询总数。
   - 覆盖的输入：
     - nlist ∈ {1, 7, 100, 1000, 4096, 8192, 10007, 32768}；
     - nprobe ∈ {1, 8, 31, 64, 128, 256, 1000, 2000}；
     - BLOCK ∈ {128, 256, 512, 1024}；
     - 7 种分布：连续、少量取值（大量并列）、全部相等、正负零混合、真实形态、大部分为 +inf、极大量级。
   - **结果：1792 个用例，0 个不同。**
2. **端到端（同一索引，G = 0、1、−1，开启检查）：**
   - 三个数据集的 G = 1 dump（1000 条查询的 probe 与 primary top-ck，b = 8）**逐字节相同**，sha256 见 `v69_results/dumps.sha256`。
   - arxiv、openai3 在每个（batch，G）下的 recall 都相同。
   - vogue 有 ±0.0002 的差别，这是 v65 自己跨进程的波动，与 v69 无关：
     - v65 在一致性运行中是 0.9642，两次计时运行中都是 0.9644；
     - v69 是 0.9643 / 0.9644。
     - 同一进程内各 G 的最终结果逐位相同；primary top-ck 逐位相同，所以差别只能来自残差阶段。

## 三、可选部分：v70 用 FP16 做质心打分（非精确）

**改动：**
- 质心打分改为 `cublasGemmEx`：输入为 FP16，在 tensor core 上计算，FP32 累加并输出；
- 质心的 FP16 副本在第一次搜索时生成，质心变化时随其他派生副本一起丢弃，graph 以副本指针为 key；
- 查询（旋转后）每批转成 FP16；
- ‖c‖² 仍是 FP32 质心的 FP32 范数，所以只有内积有舍入误差。

**为什么有效：**
- b = 8 时，FP32 的乘法要把整个质心矩阵读一遍（openai3 是 100 MB，69 µs，已达显存带宽的 82%），FP16 直接让读取量减半；
- b = 1000 时，乘法由 CUDA core 换到 tensor core。

**与 v69 的一致性（论文 α，1000 条查询；`v70_results/id_*_compare.txt`）：**

| | probe 集合完全相同的查询 | probe 平均重合度 | 最差查询 | top-ck 集合完全相同的查询 | 各（batch，G）的 recall |
|---|---:|---:|---:|---:|---|
| arxiv | 936 / 1000 | 0.99949 | 126 / 128 | 951 / 1000 | 全部相同 |
| vogue | 979 / 1000 | 0.99984 | 127 / 128 | 989 / 1000 | 全部相同 |
| openai3 | 998 / 1000 | 0.99998 | 127 / 128 | 1000 / 1000 | 全部相同 |

probe 的顺序变化较多（arxiv 只有 21 条查询的顺序完全一致），因为 FP16 会改变几乎相等的距离之间的先后。只测了论文 α；其他 α 与 nprobe 未测。

## 五、新发现：扫描候选缓冲的断崖（未实施）

**机制（与数据吻合的最可能解释，尚未直接验证，例如没有统计压缩次数）：**
- v65 的 primary 扫描把幸存候选写进大小为 cap 的缓冲，cap = 2 的幂且 ≥ ck + BLOCK；
- 当 cnt + BLOCK > cap 时触发一次完整的 bitonic 压缩，压缩后剩下 ck 个；
- 所以两次压缩之间只能吸收 h = cap − BLOCK − ck 个新幸存者。
- 当 ck 刚好低于 cap − BLOCK 时，h 接近 0，几乎每个 chunk 都要做一次 1024–2048 元素的排序。
- 分组扫描（G ≥ 1）和单 block 扫描（G = 0，arxiv、openai3 在 b ≥ 256 时用它）都用这个规则。

**B0 前沿数据（v65，G = −1，np128，`experiments/math_ablation/b0_results/frontier/`）：**

| | α（ck） | h | b = 8 QPS | 对照 |
|---|---|---:|---:|---|
| arxiv | 50（500） | 12 | 16130 | α = 75（ck 750，h 786）：18568，候选更多反而更快 |
| arxiv | 150（1500） | 36 | 10392 | α = 200（ck 2000，h 1584）：12550 |
| vogue | 48（480） | 32 | 16060 | α = 64（ck 640，h 896）：19220 |

- b = 1000 时同样明显：arxiv α = 50 为 196124，α = 75 为 238441。这时用的是单 block 扫描，两种 ck 下每 SM 都是 3 个 block，占用率相同。
- 论文工作点的 h 分别是 536（arxiv）、896（vogue）、984（openai3），都不在断崖上。
- 但 recall–QPS 曲线上 α = 50、150（arxiv）、48、128（vogue）这些点被压低了 20–40%。

**与 v53 的关系：**
- v53 曾把 cap 一律加倍，结论是负面的（`results/front6/NEGATIVES.md`）：占用率从每 SM 3 个 block 降到 2 个，代价大于收益。
- 那次的配置是 ck 1000、BLOCK 1024。
- BLOCK 512、M 96 时不一样：cap 从 1024 增到 2048，每个 block 的共享内存从 20 KB 增到 28 KB（缓冲 cap × 8 B，加 12 KB 的表），3 个 block 共 86 KB，每 SM 仍可放 3 个，不损失占用率。
- 上表中 α = 50 与 α = 75 正好是这种情况。

**建议的修复（需实测，可作为 v71）：**
- 只在 h 太小时把 cap 加倍，h 足够时保持不变，这样不影响论文工作点；
- 加倍后若会降低占用率（例如 cap 4096，45 KB），要单独测；
- 要测的是 ck 处在断崖附近的 α 点，以及论文工作点（应不变）。
